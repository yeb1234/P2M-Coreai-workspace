# 6.0.0 SmartAgents 发布说明

> 状态：现行发布记录（2026-11-20）
> 版本：`6.0.0`，代号 **SmartAgents**
> 基线：当前 `polish/design-system-refresh` 分支合并 5.0 演示 / 部署资产后的长期发布线

## 1. 为什么叫 SmartAgents

6.0 之前，工具基本是「挂在某个意图、某个模型调用链上的函数」：意图识别不到，写工具就不在工具集；换一个 LLM，能调什么、能调几次、确认规则是否还在，全要靠调用方自己保证。

6.0 把这三层拆开：

1. **意图层**：只回答「这轮大概要做什么」，决定基础 Skill 和只读工具集；
2. **工具层**：注册表 + 预算 + 超时 + 重试 + 熔断 + 审计，统一约束工具能做什么、做几次；
3. **模型层**：本地 LLM 与外部 OpenAI-compatible LLM 按兜底策略切换，模型换了，工具契约、权限和确认闸门不变。

所以「工具可以在 LLM 之间安排」不是指让模型互相调用，而是指**工具契约与模型通道解耦**：同一个 Agent 运行时，在本地 / 外部模型之间换车道时，工具集和边界仍然稳定。这是 6.0 叫 SmartAgents 的原因。

## 2. 核心链路

```text
用户消息
  ↓
前端意图识别（prompts/clientPrompts.ts）
  ↓
后端 Skill 选择（skills.py）
  ↓
工具注册表 + 预算（tool_registry.py / tool_runtime.py）
  ↓
LangChain ReAct Agent
  ↓
本地 LLM / 外部 LLM（按设置页兜底策略切换）
  ↓
工具执行包装（超时 / 重试 / 熔断 / 结果截断 / 结构化日志）
  ↓
SSE token / tool_start / interrupt / done
  ↓
前端消息、确认卡、动作回执、撤回
```

关键点：

- `question-answer` 仍然是零工具，纯知识回答不会被视频库带跑；
- 未识别意图走 `fallback`，只保留只读检索；
- 登录用户额外获得**个人动作层**，不再依赖 `note-save` 意图是否命中；
- 匿名请求过滤 `requires_login=True` 的工具，读不到别人的画像、路径、笔记。

## 3. 工具清单（13 个）

| 类别 | 工具 |
|---|---|
| 视频检索 | `search_videos` / `search_video_titles` / `get_video_summary` |
| 学习上下文 | `get_learning_profile` / `get_recent_activity` / `get_learning_goal` / `get_my_learning_path` / `recommend_next_videos` |
| 笔记检索 | `search_notes` |
| 个人动作（写） | `save_note` / `summarize_and_save_note` / `create_calendar_event` / `create_todo` |

个人动作层的约束：

- 仅登录用户可见；
- 每个工具单轮最多 1 次；
- **整轮最多 1 个写动作**；同一轮里既要存笔记又要排日历，需要拆到下一轮；
- 同一 `run_id` 内按动作类型去重，重复调用返回已有记录；
- Todo 只创建 **1 条汇总记录**，步骤写进同一个 `description`，不拆碎项。

## 4. 写动作：确认、审计、撤回

写工具不是普通工具，执行前多两道闸门：

1. `chat_agent` 的 `post_model_hook` 检测到写调用后 `interrupt`；
2. SSE 推 `hitl` 确认卡；用户确认后才注入 `confirm=True` 并进入 ToolNode，
   取消则不执行、不产生任何数据改动。

成功写入在同一 DB 事务里完成：

- 业务对象：`Note` / `CalendarEvent` / `ScheduleItem`；
- 审计记录：`AgentAction`（run、session、user、action_type、title、payload、target_id、result）；
- 工具轨迹：`AgentRun.steps`（工具名、参数、结果、耗时）。

HITL 中断时也会先把已发生的轨迹落盘，resume 后继续补全，不会丢前半段审计。

前端在 assistant 消息下渲染动作回执：

```http
GET  /api/agent-actions
POST /api/agent-actions/{action_id}/undo
```

撤回语义：

- 笔记：删除 `Note` 及其私有文件；
- 日历：删除 `CalendarEvent`；
- Todo：写 `deleted_at` 软删，保留历史；
- 动作状态 `applied → undone`，不提供 redo。

## 5. 多模型与降级

- 本地 LLM：按设置页配置的本地 OpenAI-compatible 地址；
- 外部 LLM：OpenAI-compatible provider；
- 默认外部优先，外部不可用时切本地继续回答，不直接报错；
- 429 / 5xx / 超时退避重试；鉴权错误、路径错误立即换下一家；
- SSE `done` 返回 `provider` / `degraded_from`，前端可提示本次实际用了哪套模型；
- 工具契约不随模型切换：换模型只影响推理通道，不影响工具权限、预算和确认卡。

## 6. 检索与记忆

- 三路召回：词法（pg_trgm + ILIKE）+ 向量（HNSW halfvec）+ 视频级元数据；
- 加权 RRF：`RRF_K=60`，lexical `0.8` / vector `1.2` / meta `1.5`；
- `candidate_k=30`，`rerank_top_n=20`；重排 API 失败退回 LLM 重排；
- 记忆四层：消息原文 / 会话摘要 / `MemoryItem` 长期记忆 / `UserData` 档案；
- 对话结束后异步抽取记忆，不阻塞回答。

## 8. 升级与回滚

升级：

```bash
docker compose -f docker-compose.pg.yml up -d --build
docker exec p2-siteyeb-backend-1 alembic upgrade head
```

本次新增 `agent_actions` 表，迁移 revision 为 `d7e8f9a0b1c2`，`down_revision` 为
`c0d1e2f3a4b5`。启动时 `Base.metadata.create_all` 也会兜底建表，但生产仍建议显式跑
`alembic upgrade head`。

回滚：

- 代码：回到上一个 release tag / commit，重建 backend / frontend；
- 数据：`agent_actions` 是可丢弃的审计表；笔记、日历、Todo 的业务表不受迁移破坏；
- HITL 中断中的会话：重启后不会自动恢复，需要用户重新发起该轮写动作。

## 9. 已知边界

- 单轮只允许 1 个写动作；多动作需求要拆轮；
- 日历只支持单次日程，不支持重复日程、参与者和会议室冲突检测；
- Todo 不拆子任务，步骤都在同一条 `description`；
- 撤回是反向操作，不支持 redo / 恢复撤回；
- 同步 `/api/assistant/chat` 没有 checkpointer，确认卡和真实写入以 SSE 链路为准；
- 工具指标和熔断是进程内状态，重启清零；跨天趋势要看结构化日志聚合。
