# 7.0.0 Framework Registry：框架级重构与配置资产版本库

> 状态：现行（2026-11-21）
> 分支：`feat/7.0-framework-overhaul` → `main`
> 对照 / 回退线：`P2U-3.0-LangChain` 冻结在 6.0（`cae8d1b`），标签 `v6.0.0`

## 一、这次改了什么

7.0 不是功能页更新，而是把仓库骨架、配置来源和配置治理方式一起换掉。四条主线：

1. **标准 monorepo**：根目录按职责分层，前端、后端、配置、编排、运维、展示物、运行时数据、文档各自归位。
2. **配置资产化**：提示词、检索 / 向量参数、LLM 路由、数据库连接策略、工具治理策略从散落的代码常量收进 `configs/`，再由 PostgreSQL 原生版本库管理。
3. **Git 风格治理**：在设置页内提供提交、分支、标签、diff、合并、回滚、发布与审计，不依赖外部 Git 服务。
4. **可对照发布**：7.0 只合并 `main`，`P2U-3.0-LangChain` 保持 6.0 不动，作为并排对照和回退线。

选择只合并 `main` 的原因：6.0 与 7.0 的目录和配置加载方式差异很大，保留一条完整的 6.0 分支比事后 revert 更直接；需要对比时切分支即可，确认稳定后再决定是否回收旧线。

## 三、配置资产

### 3.1 纳管清单

`configs/manifest.yaml` 是唯一白名单，slug 为 `siteyeb-config`，默认分支 `main`。当前纳管 7 个文本资产：

| 路径 | 内容 |
|---|---|
| `prompts/runtime_prompts.py` | 后端运行时提示词 |
| `prompts/clientPrompts.ts` | 前端意图识别与模板提示词 |
| `retrieval.yaml` | RRF、召回数、权重、最低向量分 |
| `vector.yaml` | embedding 模型、维度、批大小、分块、HNSW、重排 |
| `llm.yaml` | 本地 / 外部模型路由、超时、fallback、预算；不含密钥 |
| `database.yaml` | 连接池、statement / lock / idle timeout、迁移基线、治理保留策略 |
| `governance.yaml` | 工具预算、写调用上限、审计开关 |

密钥仍然只从 `.env` / 环境变量读取，不进入版本库。

### 3.2 运行时加载

- `runtime_config.py` 负责 YAML 读取、缓存和 `reload_runtime_config()`。
- `prompts.py` 从 `configs/prompts/runtime_prompts.py` 加载，并提供 `reload_runtime_prompts()`。
- `hybrid_search.py` 的 `rrf_fuse(k=...)`、`hybrid_search(candidate_k=..., min_vector_score=...)` 和三路权重均从 `retrieval.yaml` 读取。
- 发布提交后，后端下一次请求即可读取新配置；worker 进程内已导入的提示词不会自动重载，需要重启 worker。

## 四、数据库原生版本库

### 4.1 数据模型

新增 8 张表：

| 表 | 作用 |
|---|---|
| `asset_repositories` | 仓库元信息、slug、默认分支、最新提交指针 |
| `asset_branches` | 分支名、head 提交、保护标记 |
| `asset_commits` | 提交 hash、tree、父提交（支持双父合并）、作者、消息、类型 |
| `asset_blobs` | 文本内容按 sha256 去重存储 |
| `asset_entries` | tree 到 path / blob / mode 的映射 |
| `asset_tags` | 标签与目标提交 |
| `asset_audit_events` | 提交、合并、回滚、发布、导入等审计事件 |
| `asset_publications` | 发布记录：提交、目标目录、文件数、状态、操作者 |

提交 hash 由 tree、父提交、作者、消息和时间共同计算；相同文本只存一份 blob。

### 4.2 语义

- **提交**：写入工作区内容 → 生成树 → 生成 commit → 推进分支 head。
- **diff**：按文件比较 blob，新增 / 删除 / 修改分别统计行数，不做跨文件累计。
- **合并**：三路合并；无冲突自动生成双父提交，有冲突返回 409，不做文本猜测。
- **回滚**：以目标提交的树生成一个新的 rollback 提交，不移动历史。
- **工作区状态**：比较分支 tree 与 `configs/` 实际文件，给出 `dirty` 标记。
- **导入工作区**：把 `configs/` 当前内容导入为新提交，用于接管手工改动。
- **发布**：校验提交后原子写回 `configs/` 白名单文件，记录 publication 和审计事件。

### 4.3 API

管理员路由前缀 `/api/asset-registry`：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/repos` | 仓库与最新提交 |
| GET | `/repos/{slug}` | 仓库详情 |
| GET | `/repos/{slug}/commits` | 提交历史 |
| GET | `/repos/{slug}/tree?ref=` | 树 |
| GET | `/repos/{slug}/file?path=&ref=` | 单文件内容 |
| GET | `/repos/{slug}/diff?from=&to=` | 分支 / 提交 diff |
| GET | `/repos/{slug}/working-status` | 工作区脏状态 |
| GET | `/repos/{slug}/branches` | 分支 |
| GET | `/repos/{slug}/tags` | 标签 |
| POST | `/repos/{slug}/commits` | 提交 |
| POST | `/repos/{slug}/branches` | 新建分支 |
| POST | `/repos/{slug}/tags` | 打标签 |
| POST | `/repos/{slug}/merge` | 合并 |
| POST | `/repos/{slug}/rollback` | 回滚 |
| POST | `/repos/{slug}/publish` | 发布 |
| POST | `/repos/{slug}/import-working` | 导入工作区 |
| GET | `/repos/{slug}/audit` | 审计日志 |

### 4.4 权限与边界

- 所有资产库接口要求 `role=admin`；普通用户既看不到入口，也调不通接口。
- 只处理 `manifest.yaml` 白名单内的文本文件；不允许路径越界，不接管二进制、视频、模型。
- 合并冲突直接拒绝，不在服务端做模糊合并。
- 当前是单实例内的事务级并发控制，不是多主复制；同一时刻按数据库事务串行化写入。
- 发布只写 `configs/`，不自动重启 worker，不自动提交 Git；Git 与资产库是两套独立历史。

## 八、已知边界

- 资产库只存文本配置，不接管媒体、模型和数据库数据。
- 合并冲突不自动解决；冲突时需在分支上重新编辑后提交。
- 发布不会自动重启 worker；提示词类配置需要手动重启对应 worker。
- 未接外部 Git remote；Git 提交与资产库提交需要分别执行。
- 7.0 只合并 `main`，`P2U-3.0-LangChain` 保持 6.0，作为对照与回退线。
