## 5. 批量入队性能优化

**需求**: 600+ 视频批量入队时后端处理超 5 分钟，浏览器/代理超时断开，抛 `Failed to fetch`。

**根因**: `batch_ai_jobs` 对每个视频逐个调用 `create_ai_job_from_payload`，内部执行 `db.commit()`。602 个视频 ≈ 602 次 commit + 602 次 existing_job 查询 = 1200+ 次 DB 往返。

**修复**:

### 后端

- `backend/app/routers/ai_jobs.py`:
  - 删除循环内逐条 commit，改为统一构建 `AiJob` 对象后一次 `db.commit()`
  - 直接内联创建 `AiJob` + `_apply_job_options`，避免 `create_ai_job` 中的额外查询
  - 保留 `_prepare_force_rerun` 逻辑，但和创建一起纳入同一事务

### 前端

- `src/lib/videoApi.ts`: `batchAiJobs` 增加自动分块逻辑（`CHUNK_SIZE = 100`）
  - 超过 100 个 videoIds 时拆成多个请求顺序发送
  - 每批递减 `max_enqueue` 保证总上限正确
  - 合并各 chunk 的 preview 结果（eligible/enqueued/skipped/active 等累加）

## 8. 侧边栏持久化修复

**现象**: 左侧侧边栏拖拽调整图标顺序后刷新，顺序回到默认；点击"隐藏"后刷新，被隐藏的图标又全部显示。

### 根因 1：reorderNav 返回原引用

- `reorderNav` 在 `fromIdx === toIdx` 时直接返回 `{ navOrder: order }`，但 `order` 是 `state.navOrder` 的浅拷贝 `[...state.navOrder]`，无任何改动
- Zustand 的 `set` 如果返回的 state 引用与当前相同，不会触发订阅，也不会触发 `persist` middleware 的 `setItem`

**修复**: `fromIdx === toIdx` 时仍然返回 `{ navOrder: order }`，其中 `order` 是新的数组引用，确保 persist 被触发。

### 根因 2：merge 缺少异常格式防御

- Zustand v5 的 `persist` middleware 在 rehydration 时调用自定义 `merge(persisted, current)`
- 如果 storage 返回 `null`、`undefined` 或非对象值，`storageValue.state` 读取会抛异常或产生非法合并结果

**修复**:
- `merge` 开头增加双重检查：`!persisted || typeof persisted !== 'object'` 时直接返回 `current`
- 提取 `saved` 后再检查 `!saved || typeof saved !== 'object'`，异常时安全回退
- DEV 模式下增加 `console.log('[uiStore merge] ...')`，浏览器端可实时查看 hydration 数据

### 新增测试

- `src/__tests__/uiStore.test.ts`（新增）:
  - `preserves navOrder after reordering`
  - `preserves hiddenNavItems after hiding`
  - `preserves both order and hidden state together`

## 9. IT 视频站文件夹系统修复

### breadcrumb 重复点击爆炸

**根因**: `videoStore.ts` 的 `enterCategory` 追加 breadcrumb 前未判断目标 id 是否已是最后一项，连续点击同一文件夹时重复入栈。

**修复**: 追加前先判断，如果目标 id 已经是当前最后一项，直接 return。

### CategoryTree React key 重复

**根因**: 用户连续点击导致 breadcrumb 重复，渲染时 key 重复导致 React 崩溃。

**修复**:
- `VideoList.tsx` breadcrumb key 从 `b.id ?? 'root'` 改为 `` `${b.id ?? 'root'}-${i}` ``
- `CategoryTree.tsx` 新增 `deduplicateTree()`，渲染前递归去重树节点

### 切换文件夹后 children 不更新

**根因**: `VideoList.tsx` `useMemo` 依赖项是 `getCurrentChildren` 函数引用（Zustand store 中的函数引用永远不会变化），导致 `currentCategoryId` 变化后 children 从不重新计算。

**修复**: `useMemo` 依赖从 `[getCurrentChildren]` 改为 `[categoryTree, currentCategoryId]`。

## 维护原则

- Zustand persist 的 `merge` 必须对 `persisted` 做防御检查：它可能是 `null`、`undefined`、字符串、数字或 `{}`
- 任何改变数组的 store action，返回的新数组引用必须明确创建（`[...arr]`、`arr.filter(...)` 等），不能依赖旧引用
- 侧边栏的 `navOrder` 和 `hiddenNavItems` 都属于用户偏好，应随 `uiStore` 一起持久化；不要把它们拆到独立 storage 里
- 大目录批量入队时后端必须统一事务，前端必须分块发送，避免超时
- 模型下载必须走后台线程 + 状态轮询，不能同步阻塞主 worker
