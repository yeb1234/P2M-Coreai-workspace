目标版本：2.6.0  
计划基准：2.5.0  
制定日期：2026-05-11  
当前状态：已完成第一轮 2.6 小版本收口，后续继续推进真实后端 smoke、AI 任务中心 e2e 和媒体素材队列。

## 1. 2.6 总目标

2.5 已经完成性能和结构收口，2.6 不建议立刻大规模堆新插件。下一版应围绕“真实可用性”和“长期维护边界”继续推进：

- 补真实后端 smoke 测试，确认 mock 之外的完整链路可用。
- 把 AI 任务中心、视频播放列表、批处理预览这些高风险交互用 e2e 锁住。
- 继续清理深色主题里的硬编码浅色块。
- 为大视频库做进一步性能和后台任务治理准备。
- 让灵境小助手逐步接入更多页面上下文。

2.6 的一句话目标：

> 从“结构稳定”走向“真实链路稳定”，让核心工作流不仅好看、好用，还能被自动化验证。

## 3. P0：真实后端 Smoke 测试

### 3.1 背景

2.5 的 Playwright 布局测试主要走 mock API。这样截图稳定，但不能证明真实后端链路一定通。2.6 需要增加一套可选 smoke 测试，专门跑真实后端。

### 3.2 范围

真实后端 smoke 只覆盖最核心链路，不替代 mock 布局测试：

- 登录。
- 读取当前用户状态。
- 打开工作台。
- 打开 IT 视频站。
- 请求视频列表。
- 请求 AI 助手运行时设置。
- 请求后端健康检查。
- 请求 AI 任务中心状态。
- 可选：执行批处理 dry-run，但不真正入队。

### 3.3 技术方案

新增测试文件建议：

```text
tests/e2e/real-backend-smoke.spec.ts
```

运行方式建议：

```bash
P2M_E2E_REAL_BACKEND=1 P2M_E2E_USER=... P2M_E2E_PASSWORD=... npm run test:e2e -- tests/e2e/real-backend-smoke.spec.ts
```

原则：

- 默认不跑真实后端 smoke。
- 账号密码只从环境变量读取。
- 测试源码不写真实账号。
- 不依赖本机必须存在某个固定视频。
- 不做破坏性操作。

### 3.4 验收标准

- 未设置 `P2M_E2E_REAL_BACKEND=1` 时跳过。
- 设置环境变量后能完成登录和核心接口读取。
- 后端未启动时给出明确失败信息。
- 不修改数据库关键内容。

## 4. P0：AI 任务中心批处理预览 E2E

### 4.1 背景

AI 任务中心规则已经比较复杂：

- 继续未完成。
- 全部重跑。
- 只处理无字幕。
- 只补总结。
- 只重试失败。
- 外部 LLM / 本地 LLM 总结成功口径。
- dry-run 跳过原因。

2.5 已经在后端和前端收敛了规则，但 2.6 需要用 e2e 锁住用户真实操作路径。

### 4.2 测试场景

建议新增 Playwright 场景：

1. 打开视频播放器页。
2. 展开 AI 任务中心。
3. 选择“继续未完成”。
4. 点击预览。
5. 确认预览中不包含已完成视频。
6. 切换“全部重跑”。
7. 确认预览允许包含已完成视频。
8. 切换“只失败”。
9. 确认 skipped reasons 正常展示。
10. 验证确认入队按钮状态。

### 4.3 Mock 数据设计

Mock 视频应至少包含：

- 已有字幕 + 已有总结。
- 有字幕但无总结。
- 无字幕。
- AI 任务失败。
- 正在运行。
- 外部 LLM 已总结成功。

Mock dry-run 返回应包含：

- `eligible_items`
- `skipped_items`
- `skip_reasons`
- `estimated_count`

### 4.4 验收标准

- 继续未完成不会把已完成视频放入预览。
- 全部重跑可以包含已完成视频。
- 跳过原因可读。
- 批处理预览区域无横向溢出。
- 窄侧栏下按钮不撑破。

## 5. P0：视频播放列表拖拽宽度测试

### 5.1 背景

2.5 对视频播放器和右侧播放列表做了大量间距和宽度调整。用户之前多次反馈左右边距、右侧贴边、左侧宽度和视频居中问题。2.6 需要把这些关键交互用测试锁住。

### 5.2 测试场景

新增 Playwright 场景：

- 默认宽度下播放器和播放列表对齐。
- 拖动右侧播放列表变窄。
- 拖动右侧播放列表变宽。
- 宽度达到最小值时不再继续缩。
- 宽度达到最大值时不撑破页面。
- 1024 宽度下播放器和播放列表仍然可读。

### 5.3 验收标准

- 无横向滚动。
- 播放器不被右侧面板挤压到异常比例。
- 播放列表文字截断正常。
- AI 任务中心按钮不溢出。
- 拖拽后截图稳定。

## 6. P1：深色主题硬编码清理

### 6.1 背景

2.5 已经对深色主题做了大幅改进，但仍有部分旧插件页面存在硬编码浅色：

- `bg-white`
- `bg-[#faf9f7]`
- `bg-[#f3f2ef]`
- `text-[#1a1a1a]`
- `border-[#e5e2dd]`

这些会导致深色主题中出现突兀浅色块。2.6 应继续逐页清理，而不是只依赖 CSS 兜底。

### 6.2 优先页面

建议顺序：

1. AuthPage
2. Dashboard summaries
3. NotesPage
4. ReaderPage
5. SnippetsPage
6. BookmarksPage
7. CodeNavPage
8. OpenClawPage
9. TokensPage
10. ShopPage

### 6.3 技术方案

替换策略：

| 旧写法 | 新方向 |
| --- | --- |
| `bg-[#faf9f7]` | `bg-[var(--bg-elevated)]` 或 `theme-surface` |
| `bg-[#f3f2ef]` | `bg-[var(--bg-accent)]` |
| `text-[#1a1a1a]` | `text-[var(--text-primary)]` |
| `text-[#6b7280]` | `text-[var(--text-secondary)]` |
| `text-[#9ca3af]` | `text-[var(--text-muted)]` |
| `border-[#e5e2dd]` | `border-[var(--border-light)]` |

### 6.4 验收标准

- `rg "bg-white|bg-\\[#faf9f7\\]|text-\\[#1a1a1a\\]" src/components` 命中数量下降。
- 深色主题 Playwright 截图无明显浅色块。
- 不破坏浅色主题层次。

## 7. P1：缩略图和雪碧图任务治理

### 7.1 背景

大视频库中，缩略图和雪碧图生成可能成为后台压力源。2.5 已经做了按需和限制，但还没有独立任务中心。

### 7.2 目标

2.6 可以先做轻量治理，不一定一次做完整系统：

- 显示缩略图待生成数量。
- 显示雪碧图待生成数量。
- 提供暂停/继续。
- 提供失败重试。
- 设置并发或每轮上限。
- 显示最近失败原因。

### 7.3 技术方案

后端建议新增服务层：

```text
backend/app/services/media_asset_queue.py
```

前端建议新增入口：

- 可放在 IT 视频站的 AI 任务中心附近。
- 或设置页的视频管理区域。

### 7.4 验收标准

- 大目录进入视频站时不会一次性推大量生成任务。
- 用户能看见后台素材生成状态。
- 可暂停。
- 失败能重试。

## 8. P1：超大视频目录性能

### 8.1 背景

目前视频列表已经做分页、memo、缩略图请求上限等优化。若视频数量继续增长，下一步可能需要考虑更强策略。

### 8.2 候选方案

- 虚拟列表。
- 后端分页预取。
- 文件夹树懒加载。
- 缩略图按视口请求。
- 搜索结果分页。
- 历史记录和最新视频单独接口。

### 8.3 建议推进方式

先不要直接引入虚拟列表库。建议先做测量：

- 100 个视频。
- 500 个视频。
- 1000 个视频。
- 5000 个视频。

观察：

- 首次渲染时间。
- 输入搜索卡顿。
- 文件夹展开耗时。
- 缩略图请求数量。

### 8.4 验收标准

- 1000 个视频目录下列表交互仍流畅。
- 搜索输入无明显卡顿。
- 缩略图请求不会瞬间暴涨。

## 9. P2：灵境小助手上下文扩展

### 9.1 背景

2.5 已经让灵境小助手支持视频和笔记上下文，并改成状态驱动。2.6 可以继续扩展更多页面。

### 9.2 候选页面

- Todo：当前筛选、今日任务、进行中任务、已逾期任务。
- Calendar：当前选中日期、当日事件、周视图事件。
- Pomodoro：当前阶段、剩余时间、关联 Todo、今日专注统计。
- Time Center：活动提醒、倒计时、世界时钟。
- Settings：当前 AI 模型和 LLM 使用策略。

### 9.3 技术方案

扩展 `getAssistantPageContext()`：

- 每个页面一个 `buildXContext()`。
- 每个 context 有长度上限。
- 只加入用户可见或当前相关数据。
- 不把敏感设置完整暴露给 prompt，例如 API key。

### 9.4 验收标准

- 小助手在 Todo 页能回答“我今天还有什么要做”。
- 在 Calendar 页能回答“今天有什么安排”。
- 在 Pomodoro 页能回答“当前专注关联什么任务”。
- 不泄露 API key。

### 10.1 背景

2.5 已经把交互音、通知音、番茄音和背景音收敛到统一入口，但设置还可以更细。

### 10.2 候选能力

- 全局提示音音量。
- 背景音总音量。
- 交互音开关。
- 番茄音开关。
- 通知音开关。
- 声音包选择。
- 提示音预览。

### 10.3 验收标准

- 设置页能预览声音。
- 全局静音后没有组件绕过声音控制器发声。
- 音量调整持久化。

## 11. P2：后端视频列表服务继续拆分

### 11.1 背景

2.5 已经拆了 admin settings、health、AI queue、library，也做了视频列表序列化 helper。下一步可以继续把视频列表相关查询拆得更清晰。

### 11.2 候选拆分

- 分类路径拼装。
- 观看记录拼装。
- AI 任务状态拼装。
- 收藏状态拼装。
- 列表筛选条件构建。
- 搜索结果序列化。

### 11.3 验收标准

- router 只处理 HTTP 参数和响应。
- service/helper 负责业务拼装。
- 批处理和列表使用同一套完成度判断。
- 后端测试覆盖“外部 LLM 总结成功也算完成”。

## 12. 2.6 建议执行顺序

### 阶段一：测试先行

1. 真实后端 smoke 测试骨架。

## 13. 2.6 不建议做的事

为了保持版本目标清晰，2.6 暂不建议：

- 大规模重写 UI 设计系统。
- 新增太多新插件。
- 引入重型状态管理替换 Zustand。
- 把所有页面一次性迁到虚拟列表。
- 直接做公网 SaaS 化。
- 一次性重写后端视频扫描和转录流程。

2.6 应保持“小步快跑、可验证、可回滚”的节奏。

## 15. 风险和注意事项

- 真实后端 smoke 不要写死账号密码。
- 批处理 e2e 不要真的提交大量 AI 任务。
- 深色主题改造要同时看浅色主题，不要只修暗色。
- 虚拟列表不要过早引入，先测量真实瓶颈。
- 声音设置必须继续走统一 `soundController`，不要让组件自己创建 Audio。
- 小助手上下文扩展时不能泄露 API key 或敏感配置。

## 16. 结论

2.5 解决的是“复杂功能如何稳定收口”。  
2.6 要解决的是“稳定结构如何覆盖真实链路”。

如果 2.6 能完成真实后端 smoke、AI 任务中心 e2e、播放列表拖拽 e2e 和第一批深色主题硬编码清理，那么 SiteYeb / P2M CoreAI Workspace 就会从一个功能丰富的个人工作台，进一步变成一个更适合长期使用、研究和二次开发的本地 CoreAI 产品原型。
