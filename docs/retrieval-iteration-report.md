## 二、迭代过程（四轮）

### 第 1 轮：碎片检索（起点）

检索单元是单条字幕，平均 9 字。

实测「useEffect 的依赖数组」命中的是 `'UseEffect了'`（5 字）、`'依赖注入'`（就这四个字）。关键词在，上下文不在。

8 条查询只有 2 条正确，**25%**。

### 第 2 轮：语义块 + 上下文扩展（中间态，历史）

把 359 万条字幕（截至 2026-11-16 为 3,593,723 条）合并成 6 万块（565 字/块；当前 60,259 块），
并在命中后按时间窗扩上下文。

问题：**扩展放大了错误**。一条含 fastapi 的 5 字碎片，扩展成 90 秒闲聊后，看起来像相关内容。

这一步的教训：在不正确的检索单元上做后处理，只会让错误更隐蔽。时间窗扩展后来随碎片模式删除（见 `retrieval-tuning.md`）。

### 第 3 轮：切到语义块检索（质量跃升，现行路由）

直接检索 565 字的块。当时用 `retrieval_source=chunks` 环境变量切路由；该环境变量现已不存在，
块模式是现行默认（`lexical.py:159`）。

8 条查询全对（100%），但那是**原有库**（当时 8,770 个有字幕视频；截至 2026-11-16 为 8,785）。

关键修复：rerank 的「空结果」语义被代码吞掉了 —— 模型说「都不相关」返回空数组，代码却 fallback 返回原序。修正后「红烧肉」正确返回空。

### 第 4 轮：换成 cross-encoder reranker（本轮）

原来的重排是 **LLM listwise**：把 20 个候选拼进 prompt 让模型排序。

| | LLM listwise | cross-encoder |
|---|---|---|
| 延迟 | 5000ms | **484ms** |
| 确定性 | 概率性，两次结果可能不同 | 确定性 |
| 分数可用性 | 只能排序，不能当阈值 | **相关 0.99 / 无关 0.00002** |

换用硅基流动的 `BAAI/bge-reranker-v2-m3`（和库里 embedding 的 bge-m3 同家族）。

**阈值成为可能**：cross-encoder 的分数差 6 万倍，可以直接卡阈值。这是之前一直做不到的 —— 向量余弦分挤在 0.4–0.6，从来没法定阈值。

## 四、剩余问题的原因（不是参数问题）

### ① Playwright vs BrowserUse 返回空

原分 0.0236，被 0.10 阈值过滤。

但看命中的内容：「Hello大家好，欢迎来到新一节课，上一节课我们可以学习了什么是CD」—— **本来就不相关**。

真实原因是**库里没有专门对比这两个工具的内容**。demo 里那个视频讲 Agent 跳转，可能提到了 Playwright，但没有对比 BrowserUse。

**过滤是对的，问题是库内无货**，不是阈值太严。

### ② 「今天天气怎么样」返回 3 条，分数 0.8803

命中内容：「下有没有跟天气相关的函数啊，哎好像这个，原来过去给你指定的天气应该用这个…」

那个片段在讲**代码里的天气函数**，确实包含「天气」和「函数」两个词。cross-encoder 判断它和「今天天气怎么样」相关，给了 0.88。

**这不是模型错了，是意图错配**：用户问现实中天气，文档讲编程里的天气函数。语义上确实沾边。

阈值解决不了 0.88 的分数。要处理只能在 query 侧做意图分类（判断是不是生活类问题），那属于 Agent 层的职责 —— 而 Agent 那边已经有话题分流规则了（「生活/健康类不调检索」）。

**所以这个误判在实际使用中不会暴露**，只在直接调检索接口时可见。

## 五、本轮踩的坑

### 1. 数据库里路径双格式（16/50 失败）

```
/videos/xxx.mp4      容器路径，能读
D:\ITJC\xxx.mp4      Windows 路径，Linux 报 ProtocolNotFoundError
```

修：统一转成 `/videos/` 前缀。

**中间还踩了一次转义**：修脚本时写成了 `"D:////ITJC////"`（四个反斜杠），比正确值多一倍，导致转换后路径还是错的。诊断方式是直接拿数据库里的真实路径跑一次 `exists()`。

### 2. compose 的 environment 是白名单（第三次踩）

`.env` 里写了 `RERANK_API_KEY`，但 compose 的 `environment` 没有对应条目 → 容器读不到 → `mode=llm_fallback`。

前两次分别是 `WHISPER_*` 和 `EMBEDDING_BASE_URL_DOCKER`。

**这个问题已经出现三次，说明它不是偶然。** 判断方法：改完配置后，在容器里 `python -c "from app.database import settings; print(settings.xxx)"` 确认值真的进去了。

### 3. 把字符串塞进 `dict[str, float]`

想在 `timings` 里加 `rerank_mode: "cross_encoder"`，结果 Pydantic 校验失败，整个检索 500。

```
Input should be a valid number, unable to parse string as a number
```

修：mode 提到响应顶层，schema 加字段，路由层透传（**三处都要改，漏一处就是 None**）。

### 4. LM Studio 的 API 标识带实例号

加载后提示 `use the identifier "text-embedding-bge-m3@q8_0:2"`，带 `:2` 后缀。这种 ID 每次加载都可能变。

修：`lms load --identifier bge-m3` 固定标识。

### 5. 1234 端口被 Docker 残留占用

`netstat` 显示 `com.docker.backend.exe` 占着 1234，但没有任何容器映射它 —— 是停止容器后残留的转发规则。LM Studio 的 server 起不来，后端一直连着一个返回空列表的假服务。

修：LM Studio 改用 1235。

## 七、结论

**链路跑通了，质量可用，但不是完美的。**

- 高相关查询（单一概念、术语）：**0.95+，可靠**
- 抽象/比较型查询：分数偏低（0.27），但内容对
- 库内无货：正确返回空（阈值起作用）
- 关键词误导：0.88 的假阳性，靠 Agent 层的话题分流规避

调优空间还有，但**边际收益在下降**：现在 8/11，再往上要么补库（Playwright vs BrowserUse 这类内容确实没有），要么换更强的 embedding 模型，都不是调参数能解决的。

**这个结论本身就值得写进面试材料**：能说清「为什么停在这里」比「我调到了 100%」可信。
