端口号段规划：五位服务前缀 + 两位项目号

端口从「服务类型 + 项目号」直接算出来；同一项目的前端、API、数据库、缓存末两位完全一致。

2026-11-16 规则变更：旧的 base = 11000 + (n−1)×100 以及 P2 的 11100/11110/11120/11130/11140 号段已作废。 现行规则为五位端口：123xx 前端、124xx 后端 API、125xx 数据库、126xx 缓存/中间件、127xx 监控与运维。

04五条硬规则

RULE 01

容器内端口恒定

nginx 80 / API 8000 / PG 5432 / Redis 6379，永远不随项目号变。编号只出现在宿主机映射的左侧，代码里不出现任何项目端口。

RULE 02

前端不写死后端地址

生产由 nginx 同源反代 /api → backend:8000；开发由 vite proxy /api → 127.0.0.1:12402。浏览器永远只看一个 origin，CORS 退化为兜底而非主路径。

RULE 03

后端只绑回环

API 发布到 127.0.0.1:{前缀+项目号}，不绑 0.0.0.0；需要局域网调试时走前端 80/12302 的同源反代，不为 API 单独开放网卡。

RULE 04

数据库与缓存只绑回环

127.0.0.1:{前缀+项目号}，不用 0.0.0.0。机器一旦拿到公网 IP，0.0.0.0 的 5432 就是对全世界开放。

RULE 05

80 归 P2，项目隔离靠名字

localhost 的 80 只回流 P2，其他项目不得占用。compose 固定项目名 p2-siteyeb、容器由 compose 生成 p2-siteyeb-<service>-1、卷名带项目前缀；端口只是外层标识，不承担隔离职责。

06上线前自检

开容器前先确认这段是空的。有输出就说明本项目端口被别的进程先占了。

$n = 2
$ports = @(
  (12300 + $n), (12400 + $n),
  (12500 + $n), (12600 + $n),
  (12700 + $n), 80
)
Get-NetTCPConnection -State Listen |
  Where-Object { $ports -contains $_.LocalPort } |
  Select-Object LocalPort, OwningProcess

查「这个端口到底是谁」，比看 netstat 猜进程快。

$p = 12402
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -eq $p |
  ForEach-Object {
    (Get-Process -Id $_.OwningProcess).ProcessName
  }
