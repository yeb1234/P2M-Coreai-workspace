01

先写结论

2.94 的 AI 助手此前不是“模型不行”，而是检索链路有三处断点。第一，reranker 的 URL 已经以 /rerank 结尾，代码又拼了一次，实际请求打到 /rerank/rerank；200 响应里是错误 JSON，旧代码却把它当成功并返回空列表。第二，设置页里的 EMBEDDING_* 与 RERANK_* 在旧源码里根本没有被读取，改环境变量不会生效。第三，前端只调用本地正则 detectIntent，技术问题被判成 chat 时不构造 RAGChain，自然没有引用。

三处修完后，同样的 27 题从 4/27（14.8%） 提升到 18/27（66.7%）；/api/assistant/chat 从 references=[] 变成 references=6，延迟约 29.5 秒（含 4B 本地模型生成）。这不是“检索已经调满”：仍有 9 题未命中，根因是没有向量通道、字幕段是 ASR 行级碎片、以及 4B 模型在生成侧偏保守。

版本边界先钉死。 2.94 是 SQLite + FTS5 + sqlite-vec，subtitle_segments 3,592,399 条，但 subtitle_segment_embeddings 表不存在，embedding-stats 的 indexed_embeddings=0。3.0 的 PostgreSQL/pgvector 有 60,276 个 content_chunks、覆盖率 1.0，两者不能当作同一口径。3.0 的命中只作对照，不并入 2.94 的分数。

FTS5 对中文的召回缺口

同一批关键词，FTS5（unicode61）和 LIKE 的命中量差一个数量级。FTS 把中文长串当一个 token，所以 闭包、依赖注入 这类词在字幕正文里召回极弱；这是标题通道和 LIKE 回退的必要性来源。

关键词FTS5 命中LIKE 命中读法

FastAPI12110英文词也不等于精确
依赖注入6656字幕正文与标题的分布不同
装饰器5361单行字幕天然碎片化
MySQL241,452高频课程词会把结果带偏

阈值实测：min_score 0.10 与 0.0

08

下一步：先把“能答对”与“能秒回”分开

2.94 已经证明“标题通道 + LIKE + 上下文补窗”可以把一个纯词法检索从 4/27 拉到 18/27，但它也把 p95 拉到 5.7 秒，并且仍有 9 题失败。继续在 2.94 上堆正则或标题规则，收益会越来越小；真正能把分数和延迟同时拉起来的是 3.0 的 chunk 向量。

路线 A · 推荐

切到 3.0 的 60k chunk 向量

3.0 的 content_chunks 60,276 条、覆盖率 1.0，halfvec(1024)；同样的 FastAPI / 闭包 / 装饰器查询，3.0 Top1 已经落在正确课程。2.94 的 3.59M 段级向量全量成本太高，不建议硬做。

代价：这是换栈，不是 2.94 内部调参；需要接受 3.0 的 PG/Redis 依赖，并把 2.94 的 SQLite 数据迁移或双读。

路线 B · 折中

只给 2.94 抽样建向量

按 27 题 gold 视频 + 每个主题 1–2 千段建 subtitle_segment_embeddings，先验证向量通道的召回上限；再决定是否扩到全量。这样能保住 2.94 的 SQLite 架构，但只覆盖评估集，不是产品级方案。

代价：需要新建表、回填脚本和 embedding 批处理；没有 3.59M 全量的预算就不要假装全量。

必须先定的产品口径

  • “先本地，失败后外部”到底做不做自动切换？ 现在 UI 承诺、后端单 provider，两者不一致。要么实现 fallback，要么把文案改成“本地优先，不自动切换”。
  • 外部旧地址是否清掉？ token.sensenova.cn/v1 在 local_first 下不使用，但设置页仍显示，容易误导。要么同步到当前可用外部端点，要么清空。
  • 后端 detect-intent 是否还要保留？ 前端目前完全不调用它；它的结构化输出在 qwen3-4b 上降级成 general。保留会让人以为有 LLM 意图识别，实际没有。
  • 评估集的 gold 要不要扩成语义等价？ 现在 p2-020 / p2-026 的 Top1 已经接近正确答案，但单标题子串把它们判失败。扩 gold 会改变分数口径，必须先约定再改。

本轮没有做的事

没有重建 3.59M 条 FTS5 索引；没有给 2.94 建 embedding 表；没有把 reranker 的 RERANK_TOP_N / RERANK_KEEP 全接进 2.94；没有做浏览器里的设置页点击验收；没有把 detect-intent 修成可用。它们都写在上面，不藏在结论里。
